# Impeccable Design Context

## Design Context

### Users
Unraid server operators (~1500 users) who self-host Docker containers on home NAS systems. They interact entirely through Telegram — often on mobile, often while away from their server. They need to quickly assess server health, respond to incidents, and take corrective action without SSH access. Mix of power users and hobbyists who value reliability over flashiness.

### Brand Personality
**Reliable, professional, precise** — like a seasoned sysadmin who wakes you only when it matters and gives you exactly what you need to act. No fluff, no unnecessary chatter. Trustworthy and competent.

### Emotional Goals
- **Confidence & Control** — "My server is in good hands, I can act quickly when needed"
- **Calm & Reassurance** — "Everything is under control, I'll be told if something needs attention"
- **Empowerment & Clarity** — "I understand exactly what's happening and what to do about it"

### Aesthetic Direction
- **References:** Uptime Robot / Betterstack (clean status communication, professional monitoring feel) + Home Assistant (tinkerer-friendly, customizable, power-user oriented)
- **Anti-references:** Chatty consumer bots, gamified interfaces, anything that obscures data behind decoration
- **Theme:** Dark-friendly (Telegram dark mode is common among this audience). The brand icon uses warm orange (#FF8C00→#E65C00) with green accents (#4ade80) on navy (#1a1a2e)
- **Future consideration:** Web dashboard possible someday — design tokens should be portable beyond Telegram

### Design Principles

1. **Clarity over cleverness** — Every message should be instantly parseable. Status at a glance, details on demand. Use semantic emoji as visual anchors, not decoration.

2. **Action-oriented** — Every alert includes what to do about it. Buttons for common actions, not just information. Minimize the steps from "something's wrong" to "I fixed it."

3. **Respectful of attention** — Only interrupt when it matters. When you do, be precise about severity (🔴 vs ⚠️ vs ✅). Group related information, don't spam.

4. **Professional warmth** — Competent and trustworthy, not cold. Success messages celebrate briefly (✅ ✨), errors are direct without blame. The bot is a reliable colleague, not a robot.

5. **Progressive disclosure** — Summary first, details available. `/status` shows counts, tap for per-container. Alerts show the headline, buttons reveal logs/diagnostics. Respect the small screen.

### Platform Constraints
- **Telegram Markdown V1** — Bold (`*`), italic (`_`), code (`` ` ``), code blocks (` ``` `). No colors, no fonts, no custom layouts.
- **Inline keyboards** — Max ~8 buttons visible without scrolling. Callback data limited to 64 UTF-8 bytes.
- **Message limit** — 4096 characters per message. Truncate gracefully with `_(truncated)_`.
- **No persistent UI** — Each message is standalone. Use back-button navigation for multi-screen flows.

### Emoji System
Emojis are **semantic indicators**, not decoration. Each has a fixed meaning:
- Status: 🔴 critical, ⚠️ warning, ✅ success, 🟢 running, ⚪ disabled
- Actions: 🔄 restart, 🛑 stop, ▶️ start, 📋 logs, 🔍 diagnose, 🔕 mute
- Navigation: ⬅️ back, ✅ confirm, ❌ cancel
- Categories: ⭐ priority, 🛡️ protected, 👁️ watched, 💥 killable, 🚫 ignored
- Sections: 📊 status, 📈 resources, 🖥️ server, 💾 disks, 📝 manage, 🏥 health
